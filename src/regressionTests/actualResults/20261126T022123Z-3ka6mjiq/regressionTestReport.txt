The original 95 case files were unavailable. The B, E, L, C, N, S, G, P,
and W cases are reconstructions. The I, R, and Y cases implement the new
recovery, report, and summary requirements.

The expected results were written before the first test execution. They
come from three sources:

- Explicit requirements for panic mode and reports, including the exact
  summary examples and the 100-entry storage limit.
- The grammar productions written above parser functions in src/parser.c
  and the example programs in src/criteria-tests(Parser). The parser
  functions help identify observable rule names and diagnostic codes.
- The token examples in src/examples/TOKENStest.clx and errorSample.clx
  plus the token definitions in main.c. Some bundled example files
  intentionally include errors or predate current statement syntax.

The repository README documents the build environment. No standalone
grammar specification was present in this checkout. Case-specific
assumptions are recorded in the corresponding expectedResults JSON.

The scope is lexical and syntactic. Declarations, calls, returns, list
elements, and loop controls are checked against the grammar. Operator
binding is checked through the parse-tree shape reconstructed from
grammar traces. For additive and term chains, repeated children of one
production establish the flat grammar shape for a conventional left
fold. Exponentiation is checked for nested right-hand recursion.

Indentation expectations use four-column tabs and four-space examples.
The first token of the next source line may already be lookahead at a
recovery boundary when there is no associated DEDENT. Where there is an
associated DEDENT, the explicit requirement places recovery completion
before retrieval of the next token. Synthetic indentation and error
token lexemes have no documented representation. Cases involving them
assert token names and source line numbers where those are meaningful.

The syntax-code cases exercise 17 codes reachable via source programs.
E208 is assigned to a missing DEDENT. Normal lexer EOF handling emits
the outstanding DEDENTs, and block() stops at DEDENT or EOF. No supported
source-only way to reach the missing-DEDENT branch was identified. An
I-series case tests a malformed block for which the lexer never opened
an indentation level and therefore produces no associated DEDENT.

The report checks compare original errors with expected diagnostics and
independently compare consolidated rows with the original trace order.
Token names are compared across both reports for every case. Selected
token sequences, positions, and lexemes also have fixed expectations.
R01 seeds both report files with stale text in a pre-existing folder and
checks that both files were overwritten and the folder retained.

Run the preserved cases with python3 run_tests.py in WSL Ubuntu with GCC
and its sanitizer runtimes installed. Each run gets a separate directory
in actualResults. The top-level regressionTestReport.txt is the latest
result. An exit status of 1 indicates failures or cases that did not run.
